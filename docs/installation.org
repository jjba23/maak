* Requirements

- *GNU Guile 3.0 or newer* — maak is written in Guile Scheme and runs wherever Guile 3.0 runs.
- *~bash~, ~coreutils~ and ~util-linux~* — for the ~scripts/maak~ launcher
- *Tested on GNU/Linux but works anywhere Guile works* — the library itself is portable Scheme, but GNU/Linux is where it is built, packaged and exercised.
- *Optional:* [[https://guix.gnu.org/][GNU Guix]] for reproducible environments (heartily recommended), or [[https://nixos.org/][Nix]] if that is your house.
- *Optional tool modules:* ~git~, ~tar~ and ~zip~/ ~unzip~ for ~(maak git)~ and ~(maak archive)~; ~curl~ or ~wget~ for ~(maak net)~; ~podman~ or ~docker~ (and a Compose implementation) for ~(maak container)~; ~niri~ for ~(maak niri)~. Only the module that calls one needs it, and a missing program is reported as a missing program.
- *Root escalation:* ~sudo~ or ~doas~, whichever the machine has, is used by ~#:sudo?~; neither is required unless a task asks for root.

* On Guix (recommended)

maak is Guix-first: the repository ships ~guix.scm~ (the package), ~manifest.scm~ (the development environment) and ~channels.scm~ (the pinned Guix revision), so you can install or try it without leaving the functional world.

Install the current checkout into your profile:

#+begin_src shell
guix package -f ./guix.scm
#+end_src

Enter an environment with maak available, pinned to the channels this project was tested with:

#+begin_src shell
guix time-machine --channels=channels.scm -- shell -f guix.scm
#+end_src

Chain a command to it:

#+begin_src shell
guix time-machine --channels=channels.scm -- \
     shell -f guix.scm -- \
     maak --help
#+end_src

Or use the development manifest, which is how this repository itself runs its tasks:

#+begin_src shell
guix time-machine --channels=channels.scm -- \
     shell -m manifest.scm -- \
     guile -L ./src -c '((@(maak main) main))' --list
#+end_src

maak is also available *upstream in Guix* as ~maak~, in ~(gnu packages build-tools)~:

#+begin_src shell
guix package -i maak
#+end_src

Upstream currently carries an older release than this checkout; ~guix package -f ./guix.scm~ builds the tree in front of you.

* On Nix

The repository ships both a legacy ~default.nix~ and a flake:

#+begin_src shell
# Building via legacy Nix
nix-build default.nix

# Testing the result
./result/bin/maak --help

# Building via Nix Flakes
nix build
./result/bin/maak --list
#+end_src

* With Homebrew

Homebrew installs maak from its source archive through the formula in
~packaging/homebrew/Formula/maak.rb~. A formula, rather than a cask or a gem:
maak is a command-line program, so it is built from source with Guile rather
than installed from a macOS app bundle or from RubyGems.

#+begin_src shell
brew install --formula packaging/homebrew/Formula/maak.rb
#+end_src

The formula installs ~maak~, the ~maak-tasks~ helper every editor integration
uses and ~maak-zed~, with the manual page and the shell completions. It also
builds against GNU ~getopt~ and coreutils, which the launcher needs on macOS,
and byte-compiles the modules into the Cellar.

The formula's checksum is the checksum of the release's archive, so it is
refreshed after each release just as the Arch recipe's is. Install from a tagged
checkout, or after that refresh, and not from a tree whose tag has not been
published yet.

* In a container (Podman / Docker)

Prebuilt images live on Docker Hub:

https://hub.docker.com/repository/docker/jjba23/maak/general

You can also build one yourself with ~guix pack~ — see the ~package-docker~ task in ~maak.scm~ — and load the tarball with ~podman load < my.tar.gz~.

Run maak from the container, binding your filesystem so your Maak file is visible:

#+begin_src shell
docker container run -v /home/joe:/home/joe \
    docker.io/jjba23/maak:latest \
    maak -f /home/joe/hacking/maak/maak.scm --list
#+end_src

* openSUSE and other RPM distributions

~maak~ is packaged on OBS: https://build.opensuse.org/package/show/devel:tools:building/maak — download it there, or add the Zypper repository.

To build the RPM locally on Tumbleweed, install the packaging tools and set up the developer directories (see also the ~rpm-build~ task):

#+begin_src shell
sudo zypper install rpm-build rpmdevtools osc rpmlint
rpmdev-setuptree
#+end_src

Create the source tarball with ~git archive~ (or by copying the directory and running ~tar -cvzf~) and place it in =~/rpmbuild/SOURCES/=, then build:

#+begin_src shell
cp packaging/opensuse/maak.spec ~/rpmbuild/SPECS/
rpmbuild -ba ~/rpmbuild/SPECS/maak.spec
#+end_src

You should end up with:

#+begin_src shell
~/rpmbuild/RPMS/x86_64/maak-1.1.2-0.x86_64.rpm
~/rpmbuild/SRPMS/maak-1.1.2-0.src.rpm
#+end_src

Install and run it:

#+begin_src shell
sudo zypper install ~/rpmbuild/RPMS/x86_64/maak-1.1.2-0.x86_64.rpm
maak --help
#+end_src

* Debian and Ubuntu (experimental) 🧪

Install the build tools and compile the package (see also the ~deb-build~ task):

#+begin_src shell
sudo apt update
sudo apt install build-essential debhelper devscripts cme lintian guile-3.0-dev

# Unsigned binary build; copy packaging/debian/* to the root of the repo first
debuild -b -uc -us
#+end_src

* Arch Linux

~packaging/arch/PKGBUILD~ builds a package from the archive of the release tag:
it byte-compiles every module into the ~site-ccache~ that Guile reports through
~pkg-config~, and installs the launcher, the completions, the manual page, the
licence, the README and the guide. From a checkout:

#+begin_src shell
cd packaging/arch
makepkg -si
#+end_src

~makepkg~ fetches =maak-VERSION.tar.gz= from the tag on GitHub, checks its
checksum, builds it and installs the result. The recipe is in this repository
rather than in the AUR, so a change to it is a change to a pull request here,
and the checksum is refreshed from the published archive after each release.

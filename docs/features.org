#+author: Josep Bigorra

[[file:index.org][Documentation index]]

- *The entire language, not a DSL* — define functions, use lists and hash tables, write macros, import libraries. If you can write it in Guile, you can write it in a task.
- *A real command line, Make-compatible where it counts* — ~-f~, ~-C~, ~-n~, ~-k~, ~-i~, ~-j~, ~--list~ and friends behave the way your fingers expect.
- *Shell-free by default* — ~run~ takes a program and its arguments as separate strings, so a path with a space in it stays one argument.
- *Real pipelines* — ~run-pipeline~ connects argv stages with ~pipe~ and ~dup2~, reports *every* failing stage instead of just the last one, gives a stage its own environment or root (through ~sudo~ or ~doas~), keeps what each stage wrote with ~#:tee~ or ~#:capture?~ so a task can read it, and can run the whole pipeline as a background job.
- *Background jobs with a pid* — ~#:async?~ forks a process and hands back a job record you can poll, wait on, and read the exit code of.
- *Parallel tasks with readable output* — ~maak -j 4 -- fmt,lint,test~ runs tasks in forked workers and prints each one's output as a single block, in the order you named them.
- *Dry-run and quiet as lexical parameters* — ~(parameterize ((dry-run? #t)) …)~ makes destructive code safe to exercise inside a test, without a command-line flag.
- *C and C++ without a Makefile* — ~(maak cc)~ builds compiler, linker and ~ar~ commands, reads ~CFLAGS~/~CPPFLAGS~/~LDFLAGS~/~LDLIBS~ when a task asks, queries ~pkg-config~, compiles several objects in parallel, and checks ~up-to-date?~ only when the task says so.
- *Rust and Cargo, without a shell script* — ~(maak cargo)~ builds cargo and rustup commands as argv, reads ~cargo metadata~ as a value for the version and artefact paths, and leaves the build itself to cargo.
- *Python and uv, without a shell script* — ~(maak python)~ builds uv and interpreter commands as argv, reads the name, version and console scripts out of ~pyproject.toml~, and runs the four checks a Python CI runs through ~uv run~.
- *npm, pnpm and yarn behind one interface* — ~(maak frontend)~ detects the manager from the lock file and spells the verbs that differ: the frozen install, adding and removing a dependency, ~exec~, publishing, and the flag that points at a workspace member.
- *A task list in JSON, TOML or YAML* — a project that wants a list and not a language writes ~maak.yaml~, ~maak.toml~ or ~maak.json~ beside the code; ~--list~, ~--plan~, ~--watch~ and ~explain~ work the same, and a construct outside the documented subset is an error rather than a guess.
- *Maven and Gradle, without a shell script* — ~(maak maven)~ and ~(maak gradle)~ build lifecycle goals and tasks as argv, read the wrapper a checkout pins, and keep the tools' own reports available as values.
- *Emacs Lisp packages* — ~(maak elisp)~ byte-compiles in batch, runs ERT and checkdoc, and reads the headers, ~provide~ and footer a package is expected to keep, with ~elisp-practices~ naming what a file is missing.
- *Formatting and linting with sift* — ~(maak sift)~ is ~format~, ~lint~, ~check~ and ~ci~ as procedures, and it reads sift's three exit statuses instead of flattening them: a finding fails the gate with a hint about findings, a broken file fails it with a hint about the file, and ~sift-exit-meaning~ names which of the three a code was.
- *A Veritas suite in one line* — ~(veritas-test)~ is the invocation every Maak file spells out by hand: the load path, the four ~VERITAS_*~ variables and the exit, with ~veritas-shell-command~ for the variant a manifest shell re-reads.
- *A plan before the run* — ~maak --plan TASK~ records the typed plan a task describes: each command, its argv or shell line, its directory, its environment, its elevation and whether it would run in the background.  ~--plan --json~ makes it a versioned value for CI and editors.
- *A watch without a watcher* — ~maak --watch TASK~ re-runs a task when the tree changes, reloading the Maak file each time, with no watchexec or inotify binding to install.
- *The composition, explained* — ~maak explain TASK~ renders the static call graph, the load path, the escalation and a per-variable report of which environment file wins.
- *Bundles that carry their Guile* — ~(maak bundle)~ builds a self-contained ~guix pack~ of a project's automation, so it runs where neither Guile nor maak is installed.
- *Environment files and load paths* — ~.env~ files, ~-e~, ~MAAK_ENV_FILE~, ~-L~, ~MAAK_LOAD_PATH~, and ~with-load-path~ for Maak files that are a thin front end over your own modules.
- *Guix and Nix, first class* — ~manifest-shell~, ~program-shell~, time-machine variants, ~guix-container~, ~guix-pack~, mirror-image Nix helpers, and ~guix-build~ / ~guix-program~, which read a pinned Guix as *values* instead of running another Guix.
- *Git, tar and zip without a shell string* — ~(maak git)~ and ~(maak archive)~ wrap the commands a release needs, with ~#:directory~, archive prefixes and compression as arguments rather than words that a shell might split.
- *Containers, both engines* — ~(maak container)~ speaks Podman and Docker through one set of procedures, and Compose through either ~docker compose~, ~podman compose~ or ~podman-compose~; the engine is detected, not hard-coded.
- *niri, from a task* — ~(maak niri)~ wraps ~niri msg~, so the session can be queried, rearranged or screenshotted from the same place as the build.
- *Downloads with curl or wget* — ~(maak net)~ wraps the common requests: fetch a file, read a URL into a string, check a status code, post JSON, mirror a site. ~download~ picks curl or wget from what is installed.
- *Translation tooling* — the whole GNU gettext workflow (~i18n-extract~, ~i18n-merge~, ~i18n-compile~, ~i18n-refresh~) packaged so you do not rewrite it per project.
- *Errors that read like sentences* — ~task-error~ prints one line and a hint, exits non-zero, and keeps the backtrace behind ~--debug~.
- *Self-documenting tasks* — a docstring becomes the entry in ~maak --list~, laid out so long descriptions stay readable.
- *Shell completions* — Bash, Zsh and Fish, offering the tasks of the Maak file and the first line of each task's docstring.
- *A REPL workflow* — tasks are ordinary definitions, so you can develop them live from Emacs (AREI/Ares), your terminal, or whatever speaks nREPL.

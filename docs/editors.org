is maak's canonical front end, and the editor the project is developed in.  The

* Emacs (maak.el)

[[https://github.com/jjba23/maak.el][maak.el]] is maak's own Emacs front end:
pick a task, prompt for its arguments, watch the output, jump to the definition,
all from Emacs, from the same =maak.scm= the command line runs.  It lives in a
repository of its own.

* Shell completions

maak ships completions for Bash, Zsh and Fish. In a directory with a Maak file, type ~maak~, a space, then TAB, and the task names appear, each with the first line of its docstring beside it.

What a completion offers comes from two places, and neither is a second reader of the Maak file:

- the options are written once, in =src/maak/completion.scm=, and rendered for each shell;
- the tasks are asked of maak itself, as ~maak --list=completion~, so a task a macro defines, one a module the Maak file uses brings in, one a task file in JSON, TOML or YAML describes, and the ones a ~--file~ or ~--directory~ already on the line names are all offered -- they are the tasks that run would have.

The scripts are generated, never edited: =scripts/maak-completion.bash=, =.zsh= and =.fish= are copies of what ~maak --completion SHELL~ prints, ~maak completions~ rewrites them, and ~maak test~ fails when a copy and the generator disagree.  That is what keeps a flag added to the command line from being invisible to the shell that offers it.

Most installations put the scripts where each shell looks, so there is nothing to do.  By hand, ask maak for the script and write it where your shell reads completions:

#+begin_src shell
mkdir -p ~/.local/share/bash-completion/completions
maak --completion bash > ~/.local/share/bash-completion/completions/maak

maak --completion zsh  > ~/.local/share/zsh/site-functions/_maak
maak --completion fish > ~/.config/fish/completions/maak.fish
#+end_src

* Editor integrations

Every editor that can run a process gets an integration, and they all read the same task list from the same helper. [[file:../contrib/README.org][=contrib/=]] holds them, and the helper they share is =contrib/bin/maak-tasks= — a small Guile script that reads the Maak file the way maak does, and prints its tasks as JSON:

- only what the =#:export= list names, or every procedure when it exports nothing;
- each docstring, which is the task's documentation;
- each lambda list, so an editor can ask for a required argument, show the default of an optional one, take several words for a rest argument and leave a keyword argument alone — maak's command line cannot pass one;
- the prose for each argument, from the ~Args:~ section of the docstring, which is what a prompt says when it can;
- what the task declares about itself: the tasks it needs first, whether a listing should offer it, and an example invocation;
- the line the definition starts on, so a task can be visited where it is written.

The reading is maak's own =((maak tasks))= module, the one =maak --list --json= answers from (see [[file:cli.org][the command line]]), so a task is described once in this repository rather than once per consumer. What each reader is allowed to do is what differs: =maak --list --json= loads the file, so it knows every task a run would find, and the helper only reads it, so it answers while the file is halfway through an edit and on a machine with none of the project's libraries. On a file whose tasks are all written out the two agree byte for byte, which is what =contrib/test/maak-tasks.sh= checks.

The helper needs maak's libraries, and finds them beside itself in a checkout or on the load path, where an installed maak puts them. The Maak file itself is still never evaluated.  Put the helper where your shell finds it, once, for every editor below:

#+begin_src shell
install -m 755 contrib/bin/maak-tasks ~/.local/bin/maak-tasks
#+end_src

They all list the tasks the file defines, show the docstring, prompt for the
arguments — with the prose from the docstring's ~Args:~ section when it is there
— and show the tasks a task needs first.  They run the task where its output
belongs, visit a definition, and dry-run one with =maak -n=.  Neovim, Vim and VS
Code also repeat the last run, and Neovim and Vim complete task names for
=:MaakRun=.  Neovim and VS Code forget their cached task list as soon as
=maak.scm= changes, so a saved edit is what the next pick shows.

The prompts are maak.el's, because they are what maak's grammar allows: a required argument is asked for, an optional one left blank is not passed at all (and neither is anything after it), a rest argument takes any number of words, and a keyword argument is never asked for because a string never becomes a keyword. When the docstring gives an argument prose under its ~Args:~ line, that is what the prompt shows; when it does not, the editor shows the name and the default it already has, which is why the prose is worth writing.

* The REPL workflow

A REPL is an interactive environment connected to your console, your running application, your compiler — and it gives you superpowers as an engineer 🦸🏼. Lisp dialects, and Guile in particular, have excellent support for this. The author's own setup is [[https://guix.gnu.org/][Guix]], [[https://www.gnu.org/software/emacs/][Emacs]], [[https://git.sr.ht/~abcdw/emacs-arei][Arei/Ares]] and [[https://github.com/vspinu/sesman][sesman]]: an infinitely extensible editor experience, miles ahead of traditional IDEs 🐂.

It fundamentally changes the development workflow by eliminating the slow /edit, save, compile, run/ cycle:

- *Incremental development.* Write, test, inspect and evaluate one function — or one line — at a time, with immediate feedback and no full rebuild.
- *Powerful debugging.* Forget ~print~ statements and restarts: pause, inspect objects, change values, redefine a broken function on the fly, in any environment.
- *Fast prototyping.* Load a library and call its functions to learn it, which is much faster than reading documentation alone.

Integrated into your editor, you can execute any piece of code (a line, a selection, a file) with a keyboard shortcut and see the result instantly.

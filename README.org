* Every task is a λ

maak is a command runner, and its task list is a Lisp file. You write =maak.scm=
— a perfectly normal Guile module — and every procedure in it becomes a task you
can name on the command line. There is no DSL to learn and no second language to
keep in your head: the build is the program.

#+begin_src scheme
(define-module (maak)
  #:declarative? #t
  #:use-module (maak maak))

;; A task is a λ: (define (deploy) ...) is (define deploy (lambda () ...)).
(define (deploy)
  "Ship the build to the server."
  (run (list "rsync" "-av" "build/" "server:/srv/www")))

;; Procedures are values, so tasks compose like any other function.
(define (ci)
  "Everything CI does, in order."
  (fmt)
  (test)
  (deploy))
#+end_src

#+begin_src shell
$ maak ci
#+end_src

* What maak is, in fifteen seconds

- *What it is.* A command runner and control plane. You write a file called ~maak.scm~ — a perfectly normal Guile module — and every function in it becomes a runnable task.
- *Who it is for.* Lispers who want their automation to be as powerful as their editor, and everyone who is tired of Make's runes, shell-script glue, and YAML pipelines that cannot loop.
- *Why it matters.* Tasks are real Scheme functions: composable, testable, declarative, dry-runnable, parallelisable, and reproducible.

* Lisp all the way down

- *The entire language, not a DSL.* Define functions, use lists and hash tables, write macros, import libraries. If you can write it in Guile, you can write it in a task.
- *Lambdas compose.* A task calls another task with a function call, and a list of tasks is a list — no subprocess, no re-parsing a file to find out what to run.
- *Your editor already knows the language.* Docstrings are the task list, the REPL is the development loop, and =maak --list= reads like =apropos=.
- *Guix and Nix are values too.* A pin is a store path a task can decide on, not a string another tool has to interpret.
- *Shell-free by default.* ~run~ takes a program and its arguments as separate strings, so a path with a space in it stays one argument.
- *Errors that read like sentences.* ~task-error~ prints one line and a hint, exits non-zero, and keeps the backtrace behind ~--debug~.

The full list — pipelines, background jobs, ~-j~, containers, niri, downloads,
gettext — is in [[file:docs/features.org][Features]].

* Install in one line

#+begin_src shell
guix install maak
#+end_src

Guix, Nix, the container image, the RPM and the Debian package are all in
[[file:docs/installation.org][Installing maak]]. From a checkout, the launcher
runs this tree's own sources:

#+begin_src shell
guix shell -m manifest.scm -- ./scripts/maak --list
#+end_src

* Editor support

Emacs is the first-class citizen.  [[https://github.com/jjba23/maak.el][maak.el]]
is maak's canonical front end: pick a task, prompt for its arguments, watch the
output and jump to the definition, from inside Emacs, from the same =maak.scm=
the command line runs.

The other editors are also served.  Neovim, Vim, VS Code, Helix,
IntelliJ, Zed and Sublime Text each have an integration in
[[file:contrib/README.org][contrib/]] .

[[file:docs/editors.org][Editors, shells and the REPL]] has the details, and every integration has a README of its own.

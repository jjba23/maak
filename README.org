* Every task is a λ

maak is a command runner, and its task list is a Lisp file. You write =maak.scm=
— a perfectly normal Guile module — and every procedure in it becomes a task you
can name on the command line. There is no DSL to learn and no second language to
keep in your head: the build is the program.

#+begin_src scheme
(define-module (maak)
  #:declarative? #t
  #:use-module (maak maak))

;; A task is a λ: (define (build) ...) is (define build (lambda () ...)).
(define (build)
  "Compile every page in ./pages into ./build."
  (let ((out "build"))
    (mkdir-p out)
    (for-each (lambda (page)
                (run (list "pandoc" (~ "pages/~a.md" page)
                           "-o" (~ "~a/~a.html" out page))))
              '("index" "about"))
    (when (file-exists? "static/style.css")
      (cp "static/style.css" (~ "~a/style.css" out)))))

;; Two programs, one pipe, and a failure that names the stage that failed.
(define (check)
  "Lint every tracked page."
  (run-pipeline (list (list "git" "ls-files" "pages")
                      (list "xargs" "markdownlint"))))

;; Its arguments arrive as the strings typed on the command line.
(define (deploy host)
  "Ship ./build to HOST, replacing what is there."
  (unless (file-exists? "build/index.html")
    (task-error "nothing to deploy"
                #:hint "Run `maak build' first."))
  (run (list "rsync" "-av" "--delete" "build/" (~ "~a:/srv/www/" host))))

;; Procedures are values, so tasks compose like any other function.
(define (ci host)
  "Check, build and ship in one go."
  (check)
  (build)
  (deploy host))
#+end_src

The loop and the conditional expand into four commands, and =--plan= shows each
one as the argv it is — no shell to re-parse, no quote to guess at:

#+begin_src shell
$ maak --plan build
maak plan
  [1] build  mkdir -pv build
              cwd: /home/me/site
  [2] build  pandoc pages/index.md -o build/index.html
              cwd: /home/me/site
  [3] build  pandoc pages/about.md -o build/about.html
              cwd: /home/me/site
  [4] build  cp -r -v static/style.css build/style.css
              cwd: /home/me/site
#+end_src

- *Why it matters.* Tasks are real Scheme functions: composable, testable, declarative, dry-runnable, parallelisable, and reproducible.

* Lisp all the way down

- *The entire language, not a DSL.* Define functions, use lists and hash tables, write macros, import libraries. If you can write it in Guile, you can write it in a task.
- *Lambdas compose.* A task calls another task with a function call, and a list of tasks is a list — no subprocess, no re-parsing a file to find out what to run.
- *Your editor already knows the language.* Docstrings are the task list, the REPL is the development loop, and =maak --list= reads like =apropos=.
- *Guix and Nix are values too.* A pin is a store path a task can decide on, not a string another tool has to interpret.
- *Shell-free by default.* ~run~ takes a program and its arguments as separate strings, so a path with a space in it stays one argument.
- *Errors that read like sentences.* ~task-error~ prints one line and a hint, exits non-zero, and keeps the backtrace behind ~--debug~.

See the full list pipelines, background jobs, ~-j~, guix, nix, containers, niri, downloads, gettext, maven, uv, python in [[file:docs/features.org][Features]].

** How a function becomes a task

A Maak file is read, not run, when maak answers a question about it: a top-level
~define~, ~define*~ or a name bound to a ~lambda~ is a task, the ~#:export~ list
decides which of them are visible, the docstring is the documentation and the
lambda list is the argument grammar. That is what lets a listing, a plan and the
call graph be answered for a file somebody is halfway through writing, on a
machine that does not have its libraries.

* Editor support

Emacs is the first-class citizen.  [[https://github.com/jjba23/maak.el][maak.el]]
is maak's canonical front end: pick a task, prompt for its arguments, watch the
output and jump to the definition, from inside Emacs, from the same =maak.scm=
the command line runs.

The other editors are also served.  Neovim, Vim, VS Code, Helix,
IntelliJ, Zed and Sublime Text each have an integration in
[[file:contrib/README.org][contrib/]] .

[[file:docs/editors.org][Editors, shells and the REPL]] has the details, and every integration has a README of its own.

An assistant is served the same way: [[file:contrib/ai/README.org][contrib/ai]] ships a
skill file — the Maak file's rules, its vocabulary and the loop that checks the
work, as one context file — and [[file:docs/ai.org][Maak files and AI assistants]]
says what to ask maak instead of guessing.
